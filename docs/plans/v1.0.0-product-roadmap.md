# AnA v1.0.0 제품 로드맵

상태: 계획안. 이 문서는 구현 완료나 출시를 의미하지 않는다.

기존 [초기 구현 로드맵](2026-09-17-ai-orchestrator-roadmap.md)은 설계 이력으로 유지한다. 앞으로의 제품 출시 범위와 순서는 이 문서를 기준으로 논의한다. 특히 기존의 인증 연기 방침은 여러 기기에서 접속하는 제품 목표에 맞춰 변경한다.

## 1. 출시 목표와 범위

개인이 AnA 서버를 설치하고 웹, Windows, Debian KDE Plasma 데스크톱, Android 앱에서 동일한 작업과 대화를 이어갈 수 있게 한다. 독자적인 UI, 예측 가능한 에이전트 실행, 명시적인 승인, 실패 복구와 데이터 보존을 v1.0의 핵심으로 삼는다.

우선 가정은 단일 사용자·여러 기기·데몬 호스팅 방식이다. AnA 서버는 백그라운드 서비스(이하 **AnA 데몬**)로 상시 실행되며, 에이전트 CLI, DB, 워크스페이스와 작업 실행을 담당한다. 데몬은 API뿐 아니라 **웹 UI도 직접 호스팅**하고, Windows·Debian·Android 앱은 그 UI를 불러오는 **셸**이다. 앱에는 화면 코드를 따로 넣지 않는다. 클라이언트의 종료나 네트워크 단절과 작업 취소를 구분한다.

| 대상 | v1.0 범위 | 범위 밖 |
| --- | --- | --- |
| 웹 | 데몬이 호스팅하는 전체 관리·작업 기능, 반응형 독자 UI | 브라우저만으로 서버 실행 |
| Windows 앱 | 데몬 페어링, 데몬이 호스팅한 UI 표시, 알림, 파일 입출력, 셸 설치·업데이트 | Windows 네이티브 데몬·DB·CLI 일괄 설치 |
| Debian KDE Plasma 앱 | Windows와 동일한 셸 기능, KDE 환경의 설치·창·입력·파일 처리 검증 | 모든 Linux 배포판 지원 보장 |
| Android 앱 | 데몬 페어링, 모바일 배치로 표시되는 전체 기능, 알림·파일 공유 | 휴대폰에서 데몬·CLI·DB·컨테이너 실행 |
| AnA 데몬 | Linux 서비스(systemd)·Docker 설치, UI·API 단일 출처 호스팅, 업데이트·백업·복원, 기기 페어링 | 조직 계정·멀티테넌시·분산 클러스터 |

서버상의 워크스페이스와 기기 로컬 파일은 명확하게 구분한다. 파일 선택·업로드는 로컬 폴더에 대한 지속적인 실행 권한이나 자동 동기화를 의미하지 않는다. Debian PC 한 대에서 데몬과 앱을 함께 실행하는 구성은 같은 데몬을 로컬에 설치하는 것으로 지원하되, 앱 패키지에 데몬을 내장하지는 않는다.

## 2. 구조 원칙

### 데몬 호스팅 모델

- **UI는 하나, 데몬이 배포한다.** 웹 UI 빌드는 데몬과 함께 버전이 매겨지고 데몬이 제공한다. 브라우저와 세 앱은 같은 화면을 보며, UI 수정은 데몬 업데이트 한 번으로 모든 기기에 반영된다.
- **UI와 API는 같은 출처에서 제공한다.** 지금처럼 웹(3005)과 API(8100)가 나뉜 구성은 셸이 한 주소만 신뢰하기 어렵게 만든다. 데몬이 UI·HTTP API·WebSocket을 한 주소 아래에서 제공하도록 바꾼다.
- **셸이 맡는 일은 좁게 둔다.** 데몬 페어링·주소 저장, 자격 증명 보관, 연결 실패 화면, 알림, 파일 선택·다운로드·공유, 외부 링크, 셸 자체 업데이트다. 화면·상태·API 호출은 셸에 넣지 않는다.
- **네이티브 브리지는 버전이 있는 작은 API다.** 데몬 UI가 셸 기능을 부를 때 쓰는 브리지(알림, 파일, 자격 증명 등)를 명시적으로 정의하고 버전을 매긴다. UI는 브리지가 없거나 오래된 경우(일반 브라우저 포함)에도 동작해야 한다.
- **셸은 페어링한 데몬 출처만 연다.** 다른 주소로의 이동은 외부 브라우저로 넘기고, 브리지는 페어링한 출처에만 노출한다. 인증서 오류를 우회하는 옵션은 두지 않는다.
- **데몬에 닿지 못하면 셸은 그 사실만 보여준다.** 오래된 화면을 캐시해 정상인 것처럼 보이지 않게 한다. 다시 연결을 시도하고, 다른 데몬으로 바꾸는 방법을 제공한다.

### 공통

- 서버 주소, 인증, HTTP/WebSocket 연결을 화면에서 분리한다.
- shadcn 전용 생성 도구·패키지·테마 의존을 제거하고 자체 컴포넌트와 디자인 규칙을 관리한다. 접근성 기반 라이브러리까지 전부 재작성하는 것은 필수 조건이 아니다. 재사용 코드의 라이선스 고지는 보존한다.
- 셸 프레임워크는 아직 확정하지 않는다. 데몬이 화면을 호스팅하므로 후보는 웹뷰 기반 셸이다. v0.2 후속 알파에서 각 플랫폼의 최소 실행 검증 후 웹뷰 품질(한국어 입력, WebSocket, 파일 처리)·브리지 구현 부담·배포 부담을 비교해 결정한다.
- HTTP·WebSocket API와 셸 브리지를 따로 버전 관리하고 데몬·셸 호환 범위를 명시한다. 호환되지 않는 셸은 원인과 업데이트 방법을 안내한다.
- 모바일에서는 화면 배치를 바꾸되 기능의 의미와 권한을 동일하게 유지한다.

## 3. 버전별 계획

### v0.2.0-alpha.1 — 현재 기능 안정화와 독자 UI 기반

1. 남아 있는 Kimi 페일오버·입력 지연 변경과 관련 실패 테스트를 재확인하고 정리한다.
2. 색상·글꼴·여백·포커스·상태 표현을 정의하고 채팅·사이드바 시안으로 방향을 결정한다.
3. 자체 버튼·입력·메뉴·다이얼로그 등 공통 컴포넌트를 정리한다.
4. 채팅·입력창·사이드바·보관 목록·승인·질문·작업 카드에 적용한다.
5. shadcn 전용 의존과 설정을 제거하고 서버 연결 코드를 분리한다.
6. 서버 테스트·타입 검사·린트·Docker 빌드 CI를 구성한다.
7. UI가 데몬과 같은 출처에서 제공되어도 동작하도록 API·WebSocket 주소 계산을 정리한다. 실제 단일 출처 전환은 v0.3에서 한다.

완료 조건: 핵심 대화·전환·중지·승인·보관/복원 흐름, 키보드 접근성, 긴 대화 입력·스크롤 검증 통과. 기존 데이터 유지. 이번 알파에는 네이티브 앱 배포를 넣지 않는다.

### v0.2 후속 알파 → v0.2.0 — 독자 UI 완성과 앱 준비

- 설정·사용량·예약 작업 등 나머지 화면을 통일한다.
- 셸 브리지의 첫 범위(알림, 파일 선택·다운로드, 외부 링크, 자격 증명)를 정의하고 서버 이벤트·오류 형식을 정리한다.
- Windows, Debian KDE Plasma, Android에서 **데몬이 호스팅한 UI를 웹뷰 셸로 여는** 최소 검증을 한다: 화면 로드, WebSocket 스트리밍, 한국어 입력, 파일 선택, 셸 브리지 호출 하나.
- 실제 검증 결과로 셸 프레임워크, 지원 OS 최소 버전·CPU 구조, 패키지 형식을 확정한다.
- 구현 전에 화면별 기능 동등성 점검표를 작성한다.

완료 조건: 웹 전체 기능 검증과 세 플랫폼의 셸 최소 실행 검증 통과. 셸 프레임워크 선정 근거와 지원 환경 문서화.

### v0.3.0 — AnA 데몬, 인증, Windows·Debian KDE Plasma 셸

- alpha.1 — **데몬화와 단일 출처**: 서버를 systemd 서비스와 Docker 두 방식으로 설치할 수 있게 하고, UI·HTTP API·WebSocket을 한 주소에서 제공한다. 서버 인증과 기기 페어링(데몬이 발급한 일회용 코드 또는 QR로 셸 등록)을 넣는다.
- alpha.2 — **데스크톱 셸**: Windows·Debian 셸이 페어링한 데몬의 UI를 열고 채팅·스트리밍·승인·워크스페이스를 사용할 수 있다. 연결 실패 화면과 데몬 전환을 넣는다.
- 후속 알파: 셸 브리지로 알림·파일 선택·다운로드·외부 링크, OS 자격 증명 저장소 연동, 재접속과 데몬·셸 호환성 처리.
- 정식: Windows 설치 패키지와 Debian 설치 패키지(셸), 데몬 설치 패키지·스크립트, 셸 업데이트·제거 절차, 배포 서명·출처 검증 체계.
- 데몬 설치 과정의 개인 경로·UID/GID 의존을 정리하고 새 환경 설치 안내를 제공한다.
- 인증은 UI·API·WebSocket·파일 전송·관리 기능에 일관되게 적용한다. 기기 등록 해제와 세션 만료를 처리한다. 셸 없이 브라우저로 접속해도 같은 인증을 거친다.
- 원격 연결의 HTTPS/WSS 구성을 문서화하고 인증서 오류를 사용자 몰래 우회하지 않는다.
- KDE에서는 Wayland를 우선 검증하고 X11 지원 범위는 실행 검증에 따라 명시한다. 한국어 입력·배율·파일 선택·창 복원을 확인한다.

완료 조건: 깨끗한 Linux 환경에 데몬 설치→Windows·Debian KDE에서 셸 설치→페어링→작업→재접속→데몬 업데이트 후 UI 갱신 확인. 웹 기능 점검표 통과. 미인증·미페어링 접근 차단 검증.

### v0.4.0 — 실행 상태 복구와 여러 기기 일관성

- 서버를 작업 상태의 기준으로 삼고 재접속 시 스냅샷과 누락 이벤트를 복원한다.
- 요청 식별자로 같은 작업의 중복 제출을 방지하고 여러 기기의 승인 응답을 한 번만 반영한다.
- 서버 재시작 시 실행 중이던 작업의 상태를 확인해 재개 가능·결과 확인 필요·실패로 구분한다.
- 이미 실행된 커밋·게시 등 외부 작업을 무조건 재시도하지 않는다.
- 워커 결과·브랜치·부분 산출물을 보존하고 사용자 취소 시 하위 작업까지 정리한다.

완료 조건: 두 기기 동시 접속, 연결 단절, 서버 재시작, 승인 만료, 워커 시간 초과 시나리오에서 결과 유실·중복 승인·무조건적인 중복 실행 방지 확인.

### v0.5.0 — Android 셸

- alpha.1: 데몬 페어링(QR 우선), 데몬이 호스팅한 UI의 모바일 배치, 채팅, 스트리밍, 작업 상태, 승인·질문 응답.
- 후속 알파: 워크스페이스·보관·설정·사용량·예약 작업, 결과 조회, 셸 브리지로 파일 업로드/다운로드·공유 시트.
- 모바일 배치는 데몬 UI 쪽에서 반응형으로 처리한다. Android 전용 화면을 셸에 따로 만들지 않는다.
- 시스템 뒤로 가기, 키보드와 입력창, 한국어 조합 입력, 회전·화면 크기 변화를 처리한다.
- 앱 백그라운드 전환·프로세스 종료·Wi-Fi/모바일망 전환 후 서버 상태를 복원한다.
- 알림 권한 거부 시에도 앱 안에서 대기 작업을 확인할 수 있게 한다. 잠금 화면에는 기본적으로 민감한 내용을 표시하지 않는다.
- 백그라운드 푸시는 별도 전달 경로가 필요한 과제로 다룬다. 자체 호스팅 운영 조건과 외부 서비스 의존을 검토해 설계하며, 알림을 탭하면 서버에서 최신 상태를 확인한다.
- 서명한 설치 패키지와 업데이트 경로를 제공한다. 앱스토어 등록은 별도 배포 선택 사항이다.

완료 조건: 선언한 최소 Android 버전과 실제 기기에서 주요 흐름·백그라운드 복귀·네트워크 전환 검증. 전체 서버 기능의 접근 경로 제공. 폰이 오프라인일 때도 서버 작업은 유지되고 복귀 후 상태 확인 가능.

### v0.6.0 — 작업 결과 검토와 권한 강화

- 변경 파일·diff·검증 결과·커밋·산출물·worktree 충돌 정보를 작업별로 제공한다.
- 승인 대상과 파일·명령 범위를 명확하게 표현하고 작업별 범위를 검사한다.
- 지원 CLI별 게이트 적용 범위와 우회 가능성, 네이티브 하위 에이전트의 한계를 검증·문서화한다.
- 시크릿이 로그·도구 결과·화면·알림·진단 파일에 노출되지 않는지 점검한다.

완료 조건: 사용자가 변경과 검증 결과를 추적할 수 있고 범위 밖 작업·만료 승인·민감정보 노출에 대한 회귀 검증 통과. 기본 인증은 이 버전까지 미루지 않는다.

### v0.7.0 — 라우팅과 사용량 정책

- 실제 사용량·추정값·정보 없음·갱신 시점을 구분한다.
- 라우팅 이유와 에이전트 전환 이력을 보여준다.
- 작업별 예산, 재시도 횟수, 전환 한도, 종료 조건을 정의한다.
- 인증 실패·한도 소진·오래된 사용량 정보·모든 후보 실패를 검증한다.

완료 조건: 지정한 조건에서 라우팅과 종료가 예측 가능하며, 비용 정보가 없는 경우를 무료로 표시하지 않는다.

### v0.8.0 — 운영·백업·업데이트

- DB·설정·암호화 키·워크스페이스 등 복구에 필요한 항목을 구분해 백업·복원한다.
- 마이그레이션과 데몬·셸 호환성을 관리한다. DB 변경 후 이전 이미지로 돌아가는 것만으로 복구된다고 가정하지 않는다.
- UI는 데몬과 함께 바뀌므로, 데몬 업데이트가 연결된 모든 기기의 화면을 한꺼번에 바꾼다. 업데이트 중 열려 있던 화면에 새 버전을 알리고 다시 불러오게 한다. 데몬 업데이트가 실패하면 UI도 이전 버전으로 함께 돌아가야 한다.
- 예약 작업 중복 실행 방지, 로그·디스크 사용 관리, 민감정보를 제거한 진단 파일을 제공한다.
- 데몬과 각 셸 패키지의 서명·출처 검증·업데이트 실패 복구 절차를 재검증한다.

완료 조건: 새 데몬으로 데이터 복원 성공. 데몬·각 셸의 업데이트 실패 시 복구 절차 검증. 필요한 파일과 키의 누락을 사전에 탐지.

### v1.0.0 — 정식 출시

AnA 데몬 하나가 호스팅하는 같은 UI로 웹·Windows·Debian KDE Plasma·Android에서 동일한 작업을 이어갈 수 있고, 데몬과 셸의 신규 설치·업데이트·장애 복구를 문서대로 수행할 수 있는 상태로 출시한다. 지원 범위, 데몬·셸 호환 정책, 보안 문제 신고 방법, 변경 이력을 공개한다.

## 4. 공통 출시 검증

각 플랫폼에 대해 다음 항목을 통과/실패/해당 없음으로 기록하고 근거를 남긴다.

1. 셸 설치·데몬 페어링·인증·로그아웃·기기 접근 해제.
2. 채팅 전송·스트리밍·중지·페일오버·워커 결과.
3. 승인·질문·만료·여러 기기의 중복 응답 처리.
4. 워크스페이스 선택·보관·복원, 대화와 설정 유지.
5. 파일 입출력·결과 확인·외부 링크·알림.
6. 연결 단절·앱 종료·서버 재시작 후 상태 복원.
7. 한국어 입력·키보드 포커스·화면 크기·접근성.
8. 설치 패키지 검증·업데이트·제거·데이터 보존.
9. 데몬에 닿지 못할 때의 셸 화면, 데몬 업데이트 후 UI 갱신, 페어링하지 않은 출처로의 이동 차단.

## 5. 일정과 미확정 결정

날짜보다 완료 조건으로 출시를 판단한다. 의존 순서는 독자 UI와 공유 구조 → 데몬화·단일 출처·인증 → 데스크톱 셸 → 복구와 동기화 → Android 셸 → 결과 검토·운영 완성이다. 플랫폼 수를 늘리면서 기존 플랫폼의 검증을 생략하지 않는다.

구현 전에 결정할 항목은 셸 프레임워크, 셸 브리지의 범위와 버전 규칙, 페어링 방식, 지원 OS 최소 버전과 CPU 구조, Android 알림 전달 방식, 배포 서명과 업데이트 경로다. 기술 선택은 최소 실행 검증 결과로 결정하고, 외부 계정·비용·운영 정책이 필요한 선택만 사용자에게 확인한다.

데몬 호스팅 방식의 대가도 기록해 둔다. 셸은 데몬 없이는 아무것도 보여주지 못하고, 데몬 업데이트 하나가 모든 기기의 화면을 바꾼다. 앱스토어 심사가 원격에서 화면을 받아 오는 앱을 제한할 수 있어, Android 스토어 배포는 정책 확인 후 결정한다(직접 배포 APK는 영향 없음).

v1.0 이후 후보는 Windows 로컬 데몬, 셸 패키지에 데몬을 포함하는 설치 방식, 추가 Linux 배포판, 팀 계정과 역할별 권한이다. 이 문서 작성만으로 해당 기능의 구현이나 배포를 시작하지 않는다.
